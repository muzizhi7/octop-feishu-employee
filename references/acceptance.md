# 交付前逐机验收

适用：已验证的标准 macOS Octop 1.0.2 / Python 3.12 配置。安装器通过表示源码兼容，不等于飞书账号已经连接或业务数据已授权。不得将隔离安装演练称为另一台机器的真人验收。

## 从接收者开始

1. 将完整 Skill 目录装进编码代理的 Skill 目录；首先运行 doctor。接口、系统、目录不兼容时停止，不强制覆盖。
2. 运行 verify；所有测试通过，确认没有正在执行或等待确认的任务后退出 Octop。
3. install --dry-run → install → guard-enable。安装结果应包含本机备份；再次安装不得伪造备份。status 的 planned_files 应为 0。
4. 启动 Octop，连接使用者自己的模型和飞书机器人。包中不包含模型额度、App Secret、个人授权或媒体识别模型。
5. 在飞书应用中确认机器人已启用且应用已发布，使用长连接接收 `im.message.receive_v1`，卡片回调包含 `card.action.trigger`。权限与事件订阅不是一回事；发出消息成功不表示按钮回调已经配置。
6. 按机器人实际能力开通发送消息、卡片创建/更新及资源上传/下载相关权限。在本人机器人/只有本人的测试群验收；不扩大群历史读取权限、不向业务群发演示。
7. 运行 configure，检查连接和应用权限。应用权限检查通过不等于用户身份已授权；文档/任务/日历按需要获取本人授权。

## 必须观察真实结果

- 私聊发“你好”：收到短气泡，不带完成后重新生成。
- 群里 @ 机器人普通问答：默认真实引用，不自动建话题。
- 改为直接回复，保存后再次 @：无引用、无新话题；改为每次话题后新请求进入话题。切回默认引用，确认下一轮恢复。当前任务不因改设置重启。
- 请机器人用问答工具提一个两选项问题：实际出现等待状态；点击后继续执行且只执行一次。
- 长任务展开过程，暂停后后续工具不再准入；继续恢复同一次执行；停止不再发起新调用。已开始的工具或独立后台任务可能继续结束，不声称撤销外部操作。
- 只有失败/停止后的任务可以重试，须提示可能重复已有操作；已完成任务没有重新生成入口。
- 图片、普通文件、语音和视频分别真实上传、识别（依赖可用时）并回传，实际打开附件核对；识别缺失不得冒充看懂。
- 配置保存后刷新回读；错误时输入不丢；服务关闭后机器人继续使用已保存设置。
- 目标机的兼容守护已启用。未知新版或冲突应保留新版并阻断，不能承诺所有未来版本都能自动恢复。

验收时记录机器、Octop/Python 版本、通过项、受限项和日期。不同系统、架构、账号、应用或新版需重新验收，不沿用创建者的真人收发结论。

## 免 @ 专项

选择话题续聊模式并检查群消息权限后，在本人测试群新建话题：首次 @ 并给一个暗号；进入话题后不带 @ 连续两轮追问，应保留暗号和同一会话。重启 Octop 后再不带 @ 追问，验证持久记录。回到群主会话发一条不带 @ 的消息，应没有模型任务，也没有 Typing 表情；随后明确 @ 仍能正常触发。不得仅凭“有回复”判断通过，须核对用户消息的 mentions 为空且回复属于同一个 thread_id。
